# Phase 9 Newsletter - Context (decisions applied)

Source: MILESTONE-v1.1-DECISIONS.md (D-01..D-03, D-07 ideas, D-12, D-13), 09-DESIGN-CONTRACT.md, orchestrator answers.

- No standalone footer signup. Subscribers come from phase 6 (`pending` row + call to `enqueueConfirmation(email, lang)`, implemented here in `src/lib/server/newsletter.ts`; it also creates the pending row if phase 6 has not).
- Confirm token: 32 random bytes, only SHA-256 stored in `subscribers.confirm_token_hash`, 48 h in `confirm_expires_at`. Re-sending rotates the hash. GET `/newsletter/confirmer` is read-only; the button is a server action POST (idempotent; replay = "already").
- No resend route: an expired/unknown link tells the person to tick the box again on the download form. Unknown and used tokens render the same copy and never show an address (masked `m***@domain` elsewhere).
- Unsubscribe: HMAC link (`signUnsubscribe`) to `/newsletter/desinscription?s=` (GET never changes state, button = POST). RFC 8058 target is `POST /api/newsletter/unsubscribe?s=` (a `route.ts` cannot share the page's URL, so the `List-Unsubscribe` header points here; GET there redirects 303 to the page). Helpers `listUnsubscribeHeaders`, `NewsletterFooter`, `unsubscribePageUrl` added additively to `email/layout.tsx`.
- Webhook `POST /api/webhooks/resend`: Svix scheme verified with node:crypto (same algorithm as `standardwebhooks` used by the installed resend SDK; svix-* headers, webhook-* accepted), 5 min tolerance. Only `email.bounced` with `bounce.type = Permanent` and `email.complained`, only when `data.from` is on the RESEND_FROM domain (shared Resend account: other apps' events are 200-ignored, nothing recorded). Sets `suppressed` + `suppressed_reason` (`hard_bounce` | `complaint`), idempotent (`neq status suppressed`).
- Admin `/admin/newsletter`: server component (service role), filter links with counts, `?q=` substring search, 25/page, inline delete confirmation (client table), erasure = events by `request_id` of the person's download_requests, then download_requests by email, then the subscriber. Deleting a `suppressed` row is blocked (UI disabled + server check) so a bounced/complaining address cannot be mailed again.
- CSV `GET /admin/newsletter/export`: session checked in the handler, confirmed only, BOM, `;`, CRLF, `'` prefix on `= + - @ TAB CR` (also after leading whitespace), `abonnes-confirmes-AAAA-MM-JJ.csv` (Paris day).
- Legal footer identity: env `LEGAL_SENDER_NAME` + `LEGAL_POSTAL_ADDRESS`; visible placeholder only outside production.
- Shared-file touches (additive): `admin/layout.tsx` NAV + class hooks + `admin-shell.css` (mobile header), `SiteShell.tsx` (no site chrome on `/newsletter`), `ThemeProvider.tsx` (day/night honoured on `/newsletter`), `email/layout.tsx` (dark-mode css, legal line, mentions link, newsletter helpers), `.env.example`. Deviation: copy lives in `src/app/newsletter/copy.ts` (server-chosen language from the subscriber row / Accept-Language), not in `src/lib/i18n.ts` (client LanguageContext).
